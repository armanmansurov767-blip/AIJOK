# DocAgent

ИИ-агент автоматической обработки заявлений и документов студентов. Проект для конкурса «AI autumn»
(направление «ИИ-агенты и автоматизация»).

Студент отправляет заявление: файл, фото или текст. Агент читает документ, определяет тип, извлекает
поля (ФИО, группа, курс, суть, дата, подпись), проверяет полноту, записывает в журнал и готовит проект
ответа. Если поле пустое или агент не уверен, заявление уходит сотруднику на проверку. Ответ студенту
отправляется только после подтверждения сотрудником.

## Что умеет

**Студент**
- подаёт заявление без регистрации: до 5 файлов или текст;
- форматы: PDF (в том числе сканы), Word DOCX, ODT, RTF, TXT, Excel XLSX, HTML, фото JPG, PNG, WEBP, GIF;
- получает номер обращения и ссылку на страницу статуса, видит этапы обработки;
- получает ответ на почту (если настроен SMTP) и на странице статуса.

**Агент**
- читает документы моделью Claude: PDF и фото напрямую (без отдельного распознавания текста), остальное через извлечённый текст;
- определяет тип из справочника (11 типов, список меняется в `app/doc_types.json` без правки кода);
- извлекает поля, приводит ФИО к именительному падежу, оценивает уверенность в каждом поле;
- замечает несовпадения и подозрительный текст (например, попытку дать агенту указания внутри документа);
- без ключа API или при сбое модели читает документ правилами, и такое заявление всегда проверяет сотрудник.

**Сотрудник**
- входит по логину и паролю; роли «сотрудник» и «администратор»;
- видит входящие с фильтрами и поиском, оригинал документа и подсветку найденных полей;
- исправляет поля и тип, подтверждает верные значения, возвращает заявление на доработку;
- правит проект ответа и подтверждает отправку;
- ведёт журнал регистрации (номера `ВХ-2026-0001`), выгружает его в Excel (CSV);
- видит сводку по статусам и типам; администратор управляет сотрудниками.

## Запуск на своём компьютере

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env              # затем впишите ANTHROPIC_API_KEY
.venv/bin/python -m app create-user --login admin --name "Администратор" --role admin
.venv/bin/python -m app serve
```

- Портал студента: http://localhost:8000
- Кабинет сотрудника: http://localhost:8000/staff

Без `ANTHROPIC_API_KEY` всё работает, но документы читаются правилами и каждое заявление проверяет сотрудник.

## Размещение на сервере

```bash
docker build -t docagent .
docker run -d -p 8000:8000 -v docagent-data:/data --env-file .env docagent
docker exec -it <контейнер> python -m app create-user --login admin --name "Администратор" --role admin
```

Перед сервером поставьте HTTPS (например, nginx или Caddy) и задайте `DOCAGENT_SECURE_COOKIES=1`
и `DOCAGENT_PUBLIC_URL=https://ваш-адрес`. Все данные (база SQLite и загруженные файлы) лежат в одной
папке `DOCAGENT_DATA_DIR`: её нужно регулярно копировать.

## Безопасность

- Ключи и пароли только в переменных окружения или `.env`, не в коде.
- Пароли сотрудников хранятся как хеш scrypt, сессии в cookie `HttpOnly`, `SameSite=Strict`.
- Вход ограничен по числу попыток; изменения в кабинете требуют специального заголовка (защита от CSRF).
- Формат файла проверяется по содержимому, а не только по расширению. HTML и прочие файлы сотруднику
  отдаются только на скачивание, а не открываются в браузере.
- Интерфейс выводит данные из документов как текст, без вставки HTML. Строгая политика CSP.
- Текст документа передаётся модели как данные: модель предупреждена не выполнять указания из документа,
  ответ ограничен JSON-схемой, решения принимает сотрудник.
- Выгрузка журнала защищена от формул Excel в данных.

## Проверка

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest        # 43 теста: весь путь заявления, доступ, файлы, запрос к API
node demo/test_demo.js            # тест старой демо-страницы
```

Запрос к Anthropic API проверяется тестами без сети (подменённый транспорт SDK). С настоящим ключом
точность замеряется командой `python -m app evaluate` (см. `eval/README.md`).

## Устройство

```
app/
  main.py        веб-приложение и API (FastAPI)
  agent.py       шаги агента: чтение, проверка, журнал, проект ответа, действия сотрудника
  llm.py         запрос к Claude (Anthropic API), JSON-схема ответа
  rules.py       чтение без ИИ
  extract.py     приём файлов: проверка формата, извлечение текста
  doc_types.json справочник типов: ответственный, обязательные поля, шаблон ответа
  db.py          база SQLite
  security.py    пароли, сессии, ограничение попыток
  mailer.py      письма по SMTP
  evaluate.py    замер точности
  static/        интерфейс студента и сотрудника (HTML, CSS, JS без сборки)
tests/           автотесты
eval/            размеченные примеры для замера точности
demo/            первая демо-версия (одна HTML-страница)
```

## Ограничения

- Уверенность в полях оценивает сама модель, это не измеренная точность. Точность нужно замерять на
  настоящих обезличенных заявлениях (`eval/`).
- Старые форматы `.doc`, `.xls` и фото HEIC не принимаются: студенту предлагается сохранить файл как DOCX, PDF или JPG.
- Один сервер и база SQLite рассчитаны на одно учебное заведение. Для большой нагрузки нужна PostgreSQL и очередь задач.
- Все данные в примерах и тестах вымышленные.
